## How the data was de-duplicated

`backend/traces/` holds **953 trace files** but only **244 distinct canonical runs**. 624 files are replay-mode copies written each time the UI served a golden replay; one run appears up to 29×. Averaging the trace index weights each run by how often it was viewed, and it mixes in older captures with different `max_tokens` settings.

Only the newest seed trace per (category, model, pattern, item) counts as canonical; older seeds for the same slot, such as the first Category 3 and Category 6 captures, and replays of them are counted as superseded captures.

**Unit of analysis:** one canonical run per (item × rung), taken from the current golden-replay files, which match the seed traces one-to-one. Categories 3 and 6 are the exceptions. Category 3 uses all 18 quality-rerun records (3 rungs × 2 sessions × 3 repeats, n=6 per rung); its golden replays are repeat 0 of every rung. Category 6 uses all 60 fair-rerun records (4 arms × 3 incidents × 5 repeats, n=15 per arm); its golden replays are repeat 0 of three of those arms. Costs are recomputed per API call from recorded token counts, priced by the model that served the call. The traces' own `finops` blocks are not used, so the results don't depend on how the app priced them.

**Cost views.** *Billed*: cache tokens exactly as the API reported them during capture. *Warm*: every cached-prefix token is a cache read (steady state). *Cold*: the first call per model in each unit writes the prefix. All dollar figures use Anthropic's published rates, which `pricing.py` now matches. The *pre-fix card* column shows the repo's earlier $0.20 Sonnet cache-read rate.

## Issues found in the lab code and data

1. **Trace `finops` is not billed cost.** Category 5 and 6 rollups store a *modelled* cold-cache cost (`_compute_step_cold_warm`) instead of the cache tokens the API returned. This is by design and remains. *Fixed:* the rollups priced all output at Sonnet's $10/MTok (and the seed script priced mixed runs at one model's rates), so some traces had `total_cost_usd` < `output_cost_usd`. All four now use `rollup_multi_call_finops`, which prices each call at its own model's rate.
2. **CpO was zero for failed runs.** *Fixed:* `cpo_*_per_1k_usd` is now `None` for an unverified run, and the portfolio CpO and savings are `None` when a rung has no verified outcomes (`cat6_swarms/runner.py`).
3. **Naive rungs are truncated (Category 1).** Category 1 prose hits `max_tokens=2048` on most items, so its naive costs are lower bounds.
4. **Cross-rung cache warming.** Capture order lets later rungs and items read caches warmed by earlier ones (e.g. Category 4 audit-02 shows zero cache writes). The *billed* column includes this effect; the *cold* column removes it. The Category 6 fair rerun avoids it: each run writes its own cache (a per-run nonce in the cached prefix).
5. **Trace index is not de-duplicated.** `index.jsonl`/`summarize_traces()` average replays, superseded captures and session rollups together. Any dashboard built on it over-weights frequently viewed items.
6. **6 error traces** (Gemini Decision × free-text prose, live, `Connection error`) hold zero tokens and should be excluded from averages.
7. **The first Category 6 capture was biased and has been replaced.** Its shared-bus agents were truncated at `max_tokens=3200`, the capture script rejected and re-ran governed runs that failed the sandbox, and the governed patch author had explicit hints and word limits the shared-bus author lacked. The fair rerun (4 arms × 3 incidents × 5 repeats, equal output caps, per-run cold caches, no outcome-based selection, a shared-bus arm with matched instructions) replaces it; the capture script now rejects runs only for infrastructure failures.
8. **AST-SEC-01 false positive (fixed).** The constant-time-comparison check treated a comparison against a module-level scheme-prefix constant (`_SIG_PREFIX = "sha256="`) as a direct signature `==`. Three shared-bus inc-02 runs were scored 9/10 for it. Module-level names bound once to a literal now count as constants; the Category 6 numbers here use the re-scored verdicts, and the first capture's golden verdicts were unchanged by the fix.
9. **Extended thinking varies output cost (Category 3).** Calls request `thinking={"type": "between_tools"}`, yet 72 of 288 turn and probe calls in the quality rerun emitted thinking tokens (up to 3,454 in one call), billed as output; 0 of 18 compactions did. The same turn's output cost therefore varies between repeats, and the per-turn output range above includes thinking.
10. **The first Category 3 capture hard-coded the compaction stop reason** (`"end_turn"` for every summariser call), so a truncated compaction could not be seen. *Fixed:* the live path records the API's real `stop_reason` for compactions, and the golden replays, rebuilt from the quality rerun, carry the recorded stop reason of every call.
11. **The Category 2 capture script wrote a constant stop reason** (`"end_turn"` for every drafted rung, and it rewrote stored templated rungs to `end_turn`), so a truncated draft could not be seen in the replays. *Fixed:* the capture script stores the API's `stop_reason` and no longer rewrites it, and the live path returns it on each rung result. The stored drafts were not re-captured, so they still carry the constant; their normal completion is inferred from text that ends cleanly and output below the cap.
12. **The Category 2 template requires an owner and a time window for every action item** (`action_plan` items: `owner` and `target_window` are required, exactly 3 items), even when the source gives none. Measured: the judge flagged an owner or deadline the source does not support in this many templated action items: Sonnet · section template + caps 8/12 (6 serious); Haiku · section template + caps 8/12 (6 serious). *Not changed:* the model-facing prompt and schema are as captured.

## Limitations

- Small samples: 12 items (Category 1), 4 documents, 2 audits (8 questions), 3 invoices; Category 3 has 6 sessions per rung (2 scenarios × 3 repeats) and Category 6 has 15 runs per arm (3 incidents × 5 repeats). Treat percentages as indicative, not statistically robust.
- Category 6 ceiling effect: every arm verified 15/15, so these incidents are too easy to show a quality difference between context designs, and CpO equals cost per run in every arm.
- Category 2 now has a quality measurement: a deterministic fact key plus a single blind LLM judge (`claude-opus-5-5`; rubric with 3 passes per draft and position-swapped head-to-head comparisons) on one draft per rung per document (12 drafts). Judge repeats measure judge noise, not drafting variance, and no second judge or human grading cross-checks the judge's taste; the lead hand-verified the serious errors against the sources.
- Category 3 now has a quality measurement: a fixed answer key scored by deterministic string matching (no LLM judge). It checks whether specific IDs, amounts and dates survive, not whether an answer is helpful, and the recall questions are 6 per scenario (12 in all), each asked once per session.
- Several rungs change more than one lever at once (model + template, caching + step cap + projection), so savings cannot be attributed to individual levers.
- The deck's daily-volume claim (Category 6: 1.5M–10M tokens/dev/day) and its production-scale framing can't be checked from single runs.
